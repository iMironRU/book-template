# Конвергенция печати и runnable-листингов

> **Контракт-точка-правды.** Этот документ примиряет два потока — печатное издание
> (v0.3, см. `docs/handoff-v0.3-print/`) и runnable-листинги (v0.4, см.
> `docs/runnable-listings.md`) — ДО старта спринтов печати. Цель: чтобы печать не
> забетонировала решения, которые runnable потом переделывает.
>
> Спринты печати и бэклог runnable **обязаны** соблюдать этот документ. Расхождение
> артефакта с контрактом — это баг артефакта, не контракта.
>
> Статус: принят как основание v0.3. Изменения — только через CHANGELOG шаблона.

---

## Почему один документ на два потока

`print.tex` (поток 2) уже содержит примитивы, которые нужны runnable (поток 3):
окружение `\begin{onecode}` для листинга и макрос `\qrlst{#1}` для QR. Потоки
стыкуются в одну pandoc-цепочку. Если печать введёт свои соглашения (язык блока,
папку фильтров, схему QR), а runnable — свои, цепочка не соберётся. Поэтому пять
точек (C1–C5) фиксируются здесь раз и навсегда.

---

## C1. Единая грамматика блока кода

**Язык — всегда `bsl`** (так зовётся валидатор bsl-language-server; печатный черновик
использовал `onec` — отменяется). Pygments-лексер регистрируется под именем `bsl`
(файл `theme/highlight/onec_lexer.py` оставляем, имя класса роли не играет; в pipeline
зовётся как `bsl`).

**info-string несёт две вещи** — язык и режим рендера:

````
```bsl <режим>
````

где `<режим>` ∈ `runnable | contextual | conceptual` (см. `runnable §2`). Режим —
**обязателен**; блок `bsl` без режима — ошибка сборки.

**Контекст вставки — в коде**, в `//@`-хедере до первой строки кода (см. `runnable §3`):

````
```bsl contextual
//@место: модуль формы документа.ЗаказКлиента / обработчик команды
//@команда: Заполнить
&НаКлиенте
Процедура Заполнить(Команда)
    ...
КонецПроцедуры
```
````

**Кто что потребляет из одного блока:**
- режим (info-string) → runnable-пайплайн (валидация, кнопка/QR, плашка);
- тело → подсветка (`highlight-bsl`) → окружение `\begin{onecode}` в LaTeX / `<pre class="bsl">` в web;
- `//@`-хедер → плашка «Куда вставить» (`insertion-place`), затем вырезается из тела перед подсветкой.

## C2. QR и ссылки — один генератор, два источника

Единый генератор QR/ссылок. Источник URL выбирается по режиму листинга:

| Что | URL | Когда |
|---|---|---|
| Исходник листинга / главы в репо | `<qr.repo>/blob/<qr.tag>/...` (макрос `\qrlst`/`\qrchapter`) | любой листинг, глава |
| Запуск в песочнице | BSLexicon `?gzcode=…&source=…&title=…` | только `runnable` |

**Контракт BSLexicon — v1.0** (`iMironRU/BSLexicon/docs/book-integration.md`), **запинен**.
Базовый адрес `https://imironru.github.io/BSLexicon/`. Для печати/QR использовать
**`?gzcode`** (gzip → URL в 3–5× короче). Контракт не копируем в репо — ссылаемся.

**Ярлыкон — опционален.** Так как `?gzcode` укорачивает URL, сокращатель нужен не
для влезания в QR, а для аналитики и стабильности ссылок. Если API недоступен —
fallback на полный gzcode-URL (см. `runnable §5.2`).

**Поведение по форматам** (свод `print Sprint 3.4`):
- Print-PDF: QR + текстовый fallback под ним;
- Electronic-PDF: гиперссылка вместо QR;
- EPUB/HTML: кликабельная ссылка «Открыть в песочнице» / «Полный код»;
- FB2/DOCX: обычная текстовая ссылка.

## C3. Одна папка фильтров, один порядок

Все pandoc-фильтры — в **`theme/filters/`** (runnable-черновик упоминал `filters/` —
отменяется). Один упорядоченный конвейер, вызываемый из `book.sh`. Порядок —
фиксированный, потому что фильтры зависят друг от друга:

```
1. divs-to-env.lua        врезки ::: → \begin{opredelenie}            (поток 2)
2. insertion-place.lua     //@место → плашка «Куда вставить»,          (поток 3)
                           вырезает //@-хедер из тела
3. highlight-bsl.py        тело bsl → \onecode / <pre class="bsl">     (поток 2)
4. sandbox-button.lua      runnable → кнопка web / вызов \qrlst        (поток 3)
5. qr-links.py             QR главы/листинга по C2                     (потоки 2+3)
6. tikz-figures.lua        схемы .tex → векторно/растрово              (поток 2)
7. russian-typo.py         типографика (C4)                           (поток 2)
8. fb2-fallback.lua        эрзац-врезки для FB2                        (поток 2)
9. pandoc-crossref         кросс-ссылки @fig/@lst/@sec                 (поток 2)
```

Важно: `insertion-place` идёт **до** `highlight-bsl` — иначе `//@`-хедер попадёт
в подсветку как код.

## C4. Один стандарт типографики

Единый документ — **`docs/typography.md`** (печатный черновик имел
`typography-russian.md` — сводится в него). Плашки «Куда вставить» и кнопки/QR
«Открыть в песочнице» (поток 3) — типографские объекты, и их стиль **обязан
совпадать** со стилем семантических врезок (поток 2): те же отступы, линейки, кегли.
Источник стиля — `theme/divs.tex` (PDF) и `theme/divs.css` (web/EPUB); плашки
runnable добавляют свои классы в те же файлы, не заводят отдельную систему.

---

## C5. Pre-build хук — для всех форматов

Извлечение и валидация листингов (`runnable §5`) — это **pre-build стадия `book.sh`,
до pandoc, и работает для ЛЮБОГО формата**, не только print. Кнопки и плашки нужны
и в EPUB/HTML. Стадия:

```
chapters/*.md
  → извлечь bsl-блоки → разобрать режим + //@хедер
  → валидация согласованности (runnable §3.5) + словарь мест
  → lint через bsl-language-server (configs/book.bsl-language-server.json)
  → для runnable: собрать gzcode-URL (+ опц. Ярлыкон) → цель QR
  → передать артефакты в pandoc-цепочку (C3)
```

Поведение при ошибках — по `runnable §5.2` (ошибка согласованности или ERROR
линтера → сборка падает; WARNING сверх порога → падает; Ярлыкон недоступен → fallback).

## Единая схема `metadata.yaml` (добавляемые блоки)

```yaml
print:                      # поток 2 (v0.3)
  enabled: true
  trim_size: a5
  binding: kbs              # kbs | sewn | staple
  gutter: 20mm
  outer: 14mm
  top: 16mm
  bottom: 20mm
  color: grayscale         # grayscale | bw | full
  pdf_x: "1a"

qr:                         # потоки 2+3
  enabled: true
  repo: "https://github.com/iMironRU/<книга>"
  tag: "v1.0"              # автоподстановка при release
  listings_path: "listings"
  chapters_path: "chapters"

bslexicon:                  # поток 3 (v0.4)
  base_url: "https://imironru.github.io/BSLexicon/"
  contract: "1.0"          # запинено; следить за расхождением
  prefer: gzcode

yarlykon:                   # поток 3 (v0.4), опционально
  enabled: false
  namespace: "b"
```

## Карта версий

| Версия | Поток | Что вносит, соблюдая этот контракт |
|---|---|---|
| v0.3.0 | печать | `theme/print.tex`, `divs`, `highlight-bsl` (язык `bsl`!), `qr-links` (источник repo/tag), `theme/filters/` (C3), `docs/typography.md` (C4), pre-build заглушка (C5), блоки `print:`/`qr:` |
| v0.4.0 | runnable | `insertion-place`, `sandbox-button`, словарь мест, bsl-language-server, gzcode-генератор на контракте v1.0, блоки `bslexicon:`/`yarlykon:` — втыкается в готовую цепочку C3 |

Печать (v0.3) **обязана** с самого начала: язык блока `bsl` (не `onec`), папка
`theme/filters/`, pre-build стадия в `book.sh` (пусть пока пустая для runnable),
QR-генератор, готовый принять второй источник URL. Тогда runnable (v0.4) добавляется
без переделки печати.
