## Печатное издание

Серия книг `book-template` поддерживает не только электронные
форматы (EPUB/FB2/HTML/DOCX), но и **печатное издание** —
А5 ч/б PDF для малотиражной офсетной типографии.

При работе над любым параграфом нужно учитывать обе ветки
доставки: один Markdown-исходник, много форматов.

См. также:
- `spec/print-edition.md` — конституция печатного издания
- `docs/format-strategy.md` — матрица возможностей по форматам
- `docs/typography-russian.md` — правила русского набора
- `docs/print-spec.md` — требования к pre-press

### Принципы при написании

1. **Семантическая разметка важнее презентационной.**
   Не пишите «жирная рамка с двойной линейкой» —
   пишите `::: opredelenie`. Какая рамка — решает theme
   в каждом формате.

2. **Помните про ч/б.** Не закладывайте смысл в цвет.
   Цветная подсветка появится в EPUB/HTML/electronic-PDF,
   но в печатной книге — только жирность и курсив.
   Если вашу мысль читатель печатной версии **не поймёт** —
   значит зависимость от цвета слишком сильная.

3. **Помните про мобильный экран EPUB.** Не закладывайте
   смысл в точную позицию элементов на странице.
   В EPUB строки переносятся как угодно.

4. **TikZ — для схем, скриншоты — для UI.**
   Если можно нарисовать схематично — рисуйте в TikZ
   (`figures/*.tex`). Реальные скриншоты UI 1С —
   юридически сложно; временно используйте TikZ-mockups.

### Fenced divs — синтаксис врезок

```markdown
::: opredelenie
**Термин** — определение в одно-три предложения.
:::

::: napolyax
Замечание, отсылка, любопытный факт. Короче основного текста.
:::

::: primer
Конкретный пример или иллюстрация принципа. Можно с кодом.
:::

::: kontrolnye-voprosy
1. Первый вопрос?
2. Второй?
:::

::: zadanie
1. Сделать то-то.
2. Проверить, что получилось так-то.
:::
```

Правила:
- Содержимое врезки — связный фрагмент, не «кусок главы»
- Одна врезка `opredelenie` на ключевое понятие, не больше
- `kontrolnye-voprosy` — в конце параграфа, 2–5 вопросов
- Не вкладывать врезки друг в друга

### Листинги 1С

```markdown
```onec {#lst:ostatki qr-file="lst-7-1-ostatki.1cq"}
ВЫБРАТЬ
    ОстаткиТоваров.Номенклатура КАК Товар
ИЗ
    РегистрНакопления.ТоварыНаСкладах.Остатки(&МоментВремени)
        КАК ОстаткиТоваров
```
```

Правила:
- `#lst:ostatki` — id для ссылок `@lst:ostatki` ("листинг 7.1")
- `qr-file` — имя файла в `listings/`, на который ведёт
  автоматически генерируемый QR-код в печатной версии
- Подпись листинга через caption (если нужно):
  ```
  Listing: Запрос остатков канцтоваров на складе.
  ```

Не использовать ``` ```bsl ``` или ``` ```1c ``` —
для подсветки 1С только ` ```onec`.

### Схемы

```markdown
![Подпись рисунка.](figures/fig-3-1-tree.tex){#fig:tree}
```

- `.tex` — TikZ-источник, рендерится в нужный формат автоматически
- `.png` — растровый master, тоже допустим (для скриншотов)
- `{#fig:tree}` — id для ссылок `@fig:tree` ("рис. 3.1")

### Русская типографика — что писать руками

Препроцессор сам обрабатывает кавычки, тире, разряды чисел,
большинство висячих предлогов. Что писать **руками**:

- `~` между сокращением и числом: `гл.~3`, `§~7.1`, `рис.~3.1`
- `~` в инициалах: `А.~С.~Пушкин`
- `~` в спорных предлогах, где препроцессор может ошибиться

См. полные правила в `docs/typography-russian.md`.

### Что НЕ закладывать в Markdown

- Цветные элементы (цвет работает не везде)
- Фиксированные ширины и позиции
- HTML-теги напрямую (кроме крайней необходимости)
- LaTeX-команды напрямую (через `$inline$` или `{=latex}`)
- Сложные таблицы с merged cells (плохо в EPUB)
- Сложные многоколоночные разметки

Всё это идёт через семантическую разметку → theme решает,
как рендерить.

### Slash-команды для печатной стороны

- `/print-check §N.N` — проверить параграф на pre-press совместимость
- `/template-spec-review` — пройтись по spec/print-edition.md
- `/book-write` — учитывает все правила выше при написании параграфа
- `/book-analyze` — учитывает все правила выше при анализе параграфа
