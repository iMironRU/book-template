# /print-check

Проверить параграф или главу на совместимость с печатным
изданием серии.

## Параметры

- `§N.N` (опционально) — номер параграфа, например, `§3.1`
- Если не указан — берётся последний открытый/изменённый параграф

## Что проверяется

### 1. Семантическая разметка

- [ ] Все врезки использованы по назначению
  - `opredelenie` — только для ключевых определений терминов
  - `napolyax` — для дополнительных замечаний
  - `primer` — для конкретных примеров
  - `kontrolnye-voprosy` — в конце параграфа, 2–5 вопросов
- [ ] Нет вложенных врезок
- [ ] Каждая врезка содержит связный фрагмент

### 2. Листинги кода

- [ ] Все блоки 1С-кода используют ` ```onec`, не другие алиасы
- [ ] У каждого листинга есть id `{#lst:...}`
- [ ] Длинные строки укладываются в ширину A5
  (не более ~60 символов в строке)
- [ ] Указан `qr-file` для подгрузки в репозиторий

### 3. Рисунки и схемы

- [ ] Все рисунки имеют caption и id `{#fig:...}`
- [ ] TikZ-схемы лежат в `figures/*.tex`
- [ ] Скриншоты не нарушают права (только TikZ-mockups или
  явно разрешённые источники)
- [ ] Для каждого рисунка указан alt-text

### 4. Кросс-ссылки

- [ ] Все ссылки на листинги через `@lst:...`, не «листинг выше»
- [ ] Все ссылки на рисунки через `@fig:...`
- [ ] Все ссылки на параграфы через `@sec:...`

### 5. Русская типографика

- [ ] Ручные `~` стоят между сокращением и числом
  (`гл.~3`, `§~7.1`, `рис.~3.1`)
- [ ] Инициалы через `~`
- [ ] Нет ALL CAPS внутри предложений
- [ ] Нет подчёркивания как выделения
- [ ] Заголовки без точек в конце

### 6. Зависимость от цвета

- [ ] Нет фраз вроде «как показано красным», «синим выделено»
- [ ] Все смысловые выделения работают и в ч/б

### 7. Зависимость от вёрстки

- [ ] Нет «выше на странице», «справа», «ниже» — это работает
  только в одном формате
- [ ] Все позиционные отсылки заменены на семантические:
  «см. рис.~3.1», «в~листинге~3.2»

## Вывод команды

Структурированный отчёт по разделам, что найдено и что нужно
исправить, с указанием конкретных мест в тексте.

В конце — общая оценка готовности параграфа к включению
в печатное издание: `READY` / `MINOR FIXES` / `MAJOR ISSUES`.

## Использование

```
/print-check §3.1
```

Или без параметров — проверится последний параграф,
с которым шла работа.
