# Стратегия форматов: что и куда переносится

## Принцип единого источника

Один Markdown-исходник → шесть форматов:

| Формат | Назначение | Источник |
| --- | --- | --- |
| **Print-PDF** | Подача в типографию | Pandoc + memoir + Grayscale ICC |
| **Electronic-PDF** | Скачивание читателями | Pandoc + memoir |
| **EPUB3** | Магазины, читалки | Pandoc + epub.css |
| **FB2** | Русские E-Ink читалки | Pandoc + fb2-fallback |
| **HTML / mdBook** | Сайт книги | Pandoc через mdBook |
| **DOCX** | Корректор / редактор | Pandoc + reference.docx |

Каждая фича Markdown-разметки должна иметь явную стратегию
рендера в каждый из этих форматов. «Не делаем» — тоже стратегия,
но должна быть зафиксирована.

## Матрица возможностей

## Принципы

### 1. Семантическая разметка важнее презентационной

Автор пишет в терминах **смысла**, не оформления:

```markdown
::: opredelenie
**План запроса** — направленное дерево операций.
:::
```

А не:

```markdown
> **План запроса** — направленное дерево операций.
> *(серая рамка с двойной линейкой сверху и снизу)*
```

Каждый формат сам решает, как «Определение» рендерится:
PDF — двойная линейка, EPUB — рамка из CSS, FB2 — текстовый префикс.

### 2. Стратегия картинок: один master, build-time варианты

**Master-источник:**
- Схемы: TikZ-файл в `figures/*.tex`
- Скриншоты: высококачественный PNG (300+ dpi, color) в `figures/screenshots/`
- Иллюстрации (если есть): SVG в `figures/illustrations/`

**Build-time генерация в `build/figures/`:**

| Формат | Схема | Скриншот | Иллюстрация |
| --- | --- | --- | --- |
| Print-PDF | TikZ → векторно | grayscale+contrast | SVG → PDF (через pdf) |
| EPUB | TikZ → PNG 1500px | color PNG | PNG из SVG 1500px |
| HTML | TikZ → SVG | color PNG | SVG как есть |
| FB2 | TikZ → PNG 1000px | grayscale+contrast | PNG из SVG |
| DOCX | TikZ → PNG 300dpi | color PNG | PNG из SVG |

Кеширование: пересборка варианта только если master изменился
(по mtime + хеш).

### 3. Что НЕ переносится между форматами и как это терпеть

| Фича | Только в | Fallback |
| --- | --- | --- |
| Многоколоночная вёрстка | Print-PDF | Single column |
| Точные ширины таблиц | Print-PDF, HTML | Auto |
| Буквица | Print-PDF, El-PDF | Заглавная буква |
| Маргиналии | Print-PDF | `<aside>` или ничего |
| Подсветка цветом | El-PDF, HTML, EPUB | Через жирность |
| QR-коды | Print-PDF | Гиперссылка |
| Предметный указатель | Print-PDF, EPUB, HTML | Не выводится |
| Шмуцтитулы частей | Print-PDF | Заголовок раздела |

Решение в каждом случае:
- Если без фичи **смысл теряется** — переписать так,
  чтобы работало везде
- Если без фичи **смысл сохраняется**, но вид теряется —
  использовать фичу там, где поддерживается, fallback везде

### 4. Метаданные на каждый формат — формально разные ISBN

Печатная книга и EPUB — формально разные издания, требуют
разных ISBN. FB2 не требует, но желательно.

В `metadata.yaml`:

```yaml
identifiers:
  print:
    isbn: "978-5-XXXXX-XXX-X"
  epub:
    isbn: "978-5-XXXXX-YYY-Y"
    uuid: "auto-generated"
  fb2: {}
```

Pandoc передаёт правильный ISBN в каждый формат на обороте
титула / в Dublin Core / в `<title-info>`.

### 5. Версионирование — один номер на всю книгу

`metadata.yaml.version: 0.9.0` — номер книги.

Все форматы выпускаются одновременно с одним номером версии.
Если правка только в одном формате — всё равно `patch` для всей
книги (`0.9.0 → 0.9.1`).

QR-коды в печатной версии замораживаются под номер при релизе.

### 6. Тестирование на реальных устройствах

Минимальная матрица перед каждым релизом:

| Формат | Что проверять | Чем |
| --- | --- | --- |
| Print-PDF | verapdf, визуальная проверка полос | Acrobat |
| El-PDF | Закладки, ссылки | Acrobat, мобильные |
| EPUB | epubcheck, визуально | Apple Books, Calibre, PocketBook |
| FB2 | Валидация, визуально | FBReader |
| HTML | Темная тема, поиск, ссылки | Chrome, Safari, mobile |
| DOCX | Стили, корректура | Word, LibreOffice |

Это не автоматизируется полностью — нужен ручной просмотр
по списку перед каждым релизом.

## Доска решений

Открытые вопросы, которые решаются авторитарно при необходимости:

- **FB2 для технических книг с кодом и врезками?** Эрзац-врезки
  выглядят бедно. Решение: оставляем включённым по умолчанию,
  отключаем для конкретной книги через `formats.fb2: false`,
  если автор недоволен качеством.
- **KFX/MOBI для Kindle?** Не выпускаем нативно, но
  даём EPUB, который Kindle открывает через свой конвертер.
- **PDF/A для архивирования?** Включаем как отдельный таргет
  `./book.sh build archive` для научных библиотек.
- **Accessible EPUB по WCAG?** Делаем базовый уровень (alt-text,
  language, ARIA-роли). Полное соответствие — отдельная работа
  если потребуется международная дистрибуция.
