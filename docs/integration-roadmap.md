## 3. Архитектура интеграции — общий хребет

Главное: `print.tex` (поток 2) уже содержит крючки `\begin{onecode}` и `\qrlst{#1}`,
которые нужны runnable-листингам (поток 3). Потоки 2 и 3 склеиваются в одну
pandoc-цепочку. Поток 1 (ревью) стоит в стороне — он до сборки.

```
chapters/*.md
   │
   ▼  PRE-BUILD ХУК  ◄── поток 3 (runnable §5): до pandoc, для ВСЕХ форматов
   ├─ извлечь fenced ```bsl
   ├─ распарсить info-string (режим) + //@место (контекст вставки)
   ├─ валидация по dictionaries/places.yaml + правила §3.5
   ├─ lint через bsl-language-server (configs/book.bsl-language-server.json)
   └─ runnable → URL BSLexicon → Ярлыкон (короткий) → цель QR
   │
   ▼  PANDOC  (--template=theme/print.tex для print)
   │  объединённая цепочка theme/filters/ (2+3):
   │   1. divs-to-env.lua       врезки → \begin{opredelenie}        ◄ поток 2
   │   2. highlight-bsl.py      подсветка → \begin{onecode}          ◄ поток 2
   │   3. insertion-place.lua   плашка «Куда вставить» из //@место   ◄ поток 3
   │   4. sandbox-button.lua    кнопка web / \qrlst{} print          ◄ поток 3
   │   5. qr-links.py           QR главы/листинга                    ◄ потоки 2+3
   │   6. tikz / russian-typo / fb2-fallback / pandoc-crossref       ◄ поток 2
   │
   ▼  print.tex даёт примитивы:  \onecode,  \qrlst,  врезки,  типографика
```

## 4. Конвергенция: коллизии потоков 2 и 3 (решить ДО старта печати)

Чтобы поток 2 не забетонировал решения, которые поток 3 потом переделывает:

| # | Коллизия | Решение |
|---|----------|---------|
| C1 | Язык блока: `onec` (печать) vs `bsl` (runnable) | Унифицировать на **`bsl`** (так зовётся валидатор). info-string ` ```bsl runnable ` несёт язык (→ подсветка) и режим (→ runnable). Лексер регистрируем под `bsl`. |
| C2 | QR определён дважды (печать repo/tag; runnable shortlink песочницы) | Один генератор, два источника URL по режиму. `metadata.yaml` получает и `qr:`, и `bslexicon:`/`yarlykon:`. |
| C3 | Папка фильтров `theme/filters/` vs `filters/` | Одна — `theme/filters/`, одна упорядоченная цепочка в `book.sh`. |
| C4 | Типографика `typography-russian.md` vs `typography.md` | Один стандарт: плашки/кнопки (поток 3) обязаны совпадать со стилем врезок (поток 2). |
| C5 | Pre-build хук | Запускать перед pandoc во **всех** форматах, не только print. |

Эти решения зафиксированы в **`spec/print-convergence.md`** (шаг F3 ✅) — контракт-точка-правды
для спринтов печати и бэклога runnable.

## 8. Что получаем (по функциям и результатам)

Порядок работ: **сначала достраиваем стандарт в шаблоне → потом «приглаживаем»
книги под него** (`sync` + ручная доводка контента).

## 9. Стиль: единый канон и защита от дрейфа

### 9.1 Решение

Единый канон письма — `docs/style-guide.md` (создан в v0.2). Ориентир — **советский
академический учебник**, адресация **«мы»+«вы»** (без «ты»). Книги тянут канон через
`sync`; у книги остаётся тонкая надстройка (терминологический минимум, сквозной
пример, дельта для книг «для опытных»). Свод 15 правил-ядра из пяти книг.

### 9.2 Находка: дрейф в книге про регистры

Аудит показал — стиль разъехался, и не только в тоне. `1c-registers-book` ушёл от
де-факто голоса серии:

| Ось | Канон (как в книге про код) | registers (по факту в тексте) |
|---|---|---|
| Обращение | «вы» + авторское «мы» (вы:1847 / ты:92) | «ты» + авторское «я» (ты:110 / вы:198) |
| Аббревиатуры | полное название в прозе | РС/РН/РБ/РР в тексте |
| Перегрузка терминов | проговаривать роль | смешение «Остатки» (имя/вид/ВТ) |
| Ссылки | повторить кратко здесь | forward-ссылки «см. §A3» |

Тонкость: в `registers/docs/style-guide.md` лечение уже **записано** (разделы про
аббревиатуры, «повторить вместо ссылки», перегрузку), но формулировка «при следующей
правке расшифровать» = **долг признан, но не выплачен**: правила исправлены, проза — нет.

### 9.3 Корень проблемы

1. Не было единого источника — книга про код голос не кодифицировала, дрейфу не от
   чего отталкиваться; у каждой книги свои правила.
2. Правила — проза, которую никто не проверяет механически. «Написано в гайде» ≠
   «соблюдено в тексте», разрыв копится.

### 9.4 Система защиты — три слоя

1. **Один канон** (9.1) — источник правды, тянется через `sync`.
2. **Механический линтер `scripts/style-lint.py`** (рядом с `review.py`) — детектит
   детерминированное и падает в CI:
   - обращение не по канону (`ты`/`тебя`/`твой`, авторское `я`) — ошибка;
   - аббревиатуры предметки (`РС`/`РН`/`РБ`/`РР`) вне блоков кода — ошибка;
   - forward/back-ссылки (`см. §`, `как было в §`) — предупреждение;
   - канцелярит, шаблонные зачины — ошибка;
   - эмодзи, тяжёлое форматирование (>25%) — предупреждение.
3. **Роль `openai-style` в `review.py`** добивает недетектируемое: перегрузка
   терминов, сломанные метафоры, ощущение голоса — судит по единому канону.

Честная граница: линтер ловит дёшево и грубо; смысл (термины, метафоры) — панель и человек.

### 9.5 Выплата долга (remediation)

Разовый проход на книгу, **registers первый**: линтер → отчёт по файлам/строкам →
пакетная правка (`ты→вы/мы`, расшифровать аббревиатуры, ссылки→повтор, убрать
канцелярит) → панель на спорных параграфах → линтер зелёный → CI-гейт включён.

### 9.6 Вопрос закрыт (2026-08-27)

**registers выровнен под канон.** Автор выбрал выравнивание, не исключение.
Переведено: 211 форм адресации (местоимения, глаголы 2 лица единственного числа,
согласование прошедшего времени), 61 форма повелительного наклонения, 5 случаев
авторского «я», 135 аббревиатур РС/РН/РБ/РР расшифрованы с согласованием падежа.
Прямая речь в кавычках и синтаксис платформы (`РН.Остатки`) оставлены как есть —
канон выводит их из-под правил.

Послаблений в `metadata.yaml` больше нет: линтер работает на книге в полной
строгости, гейт в CI активен. Запись — в `1c-registers-book/spec/decisions.md`.

## 10. BSLexicon: контракт URL принят (для v0.4)

Прочитан `iMironRU/BSLexicon/docs/book-integration.md` — **контракт v1.0** (2026-06-22).
Решение: **берём**, это зависимость потока 3 (runnable-листинги).

- Параметры: `?code` (URL-safe base64), `?gzcode` (gzip — в 3–5× короче, для QR/печати),
  `?source` + `?title` (провенанс-баннер), `?embed=1` (iframe). Базовый адрес —
  `https://imironru.github.io/BSLexicon/`. Дан готовый JS-генератор `bslToUrl`/`bslToUrlGz`.
- **Следствие 1:** `?gzcode` понижает Ярлыкон из «обязательного для QR» в
  «опционально: аналитика + стабильность ссылок». Упрощает v0.4.
- **Следствие 2:** контракт версионируется (новые параметры — минор, смена семантики —
  мажор с анонсом). **Запинить** `bslexicon.contract: "1.0"` в `metadata.yaml`.
- Контракт **не копируем** в репо (живёт у BSLexicon, `runnable §7`) — ссылаемся.
- При старте v0.4 обновить `docs/runnable-listings.md §5/§7/§8`: добавить `?gzcode`/`?title`,
  понизить Ярлыкон до опционального; `tools/generate-sandbox-links` строить на `bslToUrlGz`;
  блок `metadata.yaml`:
  ```yaml
  bslexicon:
